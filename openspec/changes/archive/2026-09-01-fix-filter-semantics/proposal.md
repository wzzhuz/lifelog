# 筛选器语义：状态与分类是两组，不是一组

## 对应反馈

「全部」和「汽车」可以同时选上，然后只展示汽车标签的——这似乎是个 bug。

## 核实结论：不是 bug，是设计缺陷

**逻辑是对的，视觉在骗人。**

代码里其实是两个独立的筛选维度：

| 维度 | 字段 | 取值 | 关系 |
|---|---|---|---|
| 状态 | `filter` | 全部 / 该做了 / 待记录 / 已钉选 | 单选，互斥 |
| 分类 | `tag` | 个人 / 家务 / 健康 / 汽车 … | 单选，可清空 |

两者是**正交的「与」关系**：

```
状态=全部 → 不限制状态
分类=汽车 → 只看汽车标签
结果   → 汽车标签下所有状态的事件
```

这个结果是正确的。

**问题出在 UI**：两组不同维度的筛选器被放在同一行、用完全相同的
`FilterChip` 样式呈现，用户理所当然认为它们是一组互斥选项。

看到「全部」和「汽车」同时高亮，任何人都会觉得矛盾。

## 做什么

### 1. 视觉分组，明确标注

改为两行，各自带标签：

```
状态   [全部] [该做了] [待记录] [已钉选]
分类   [个人] [家务] [健康] [汽车] …
```

- 分类行仅在存在标签时显示
- 两行之间加分隔
- 分类组末尾加一个「不限」用于清空标签筛选

### 2. 「全部」改名为「不限」

「全部」这个词暗示「包含一切」，选中它却还能被分类过滤，本身就矛盾。
「不限」准确表达「本维度不做限制」。

### 3. 状态筛选与分类筛选互不干扰

- 点「不限」只重置状态维度，不影响已选的分类
- 点分类「不限」只清空分类，不影响状态

## 不做什么

- ❌ 不改成多选标签（同时选「个人」+「健康」）——当前场景用不上，
  且会让「与/或」语义再次变模糊
- ❌ 不合并两个维度（它们本来就该分开）

## 一个附带发现

`ListUiState.allTags` 是从**当前可见事件**推导标签列表的，
意味着筛选后标签行会跟着变少。这会让用户困惑——
刚选了「汽车」，结果分类行只剩「汽车」一个可点了。

建议改为从**全部事件**推导标签，保持分类行稳定。
