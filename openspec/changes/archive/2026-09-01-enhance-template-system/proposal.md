# 模板体系增强：可重复导入、扩充模板、支持外部导入

## 对应需求

- 需求 1：模板导入只出现一次，首次没勾全就再也找不回来
- 需求 4：补充夫妻日常、吃药、身体调理类模板
- 需求 5：支持从外部导入模板文件（元宝生成后直接导入）

## 为什么改

**需求 1 的根因**：`从模板导入` 按钮只在**空状态页**出现。
一旦有了事件，那个页面就再也不会显示，入口等于一次性。

这不是「用户没仔细看」，是设计缺陷——
首次启动时用户根本不知道自己会用到哪些模板，
让他在那个时刻一次性做决定，本身就是错的。

**需求 5 的场景**：让元宝生成一份模板 JSON，
在 App 里选文件导入。比在手机上一个个手打事件快得多。

## 做什么

### 1. 设置页加「从模板导入」入口

- 位置：设置页新增「模板」分组，与「备份与恢复」并列
- 可重复进入，展示全部内置模板的多选列表
- **已存在的同名事件默认置灰并标注「已添加」**，避免重复导入
- 支持全选 / 取消全选

### 2. 扩充内置模板

在现有 24 个基础上补充，重点覆盖：

**健康调理类**：吃药、中药调理、针灸、贴膏药、量血压、测血糖
**夫妻日常类**：同房、约会、结婚纪念日、一起看电影

### 3. 支持外部导入模板文件

- 入口：设置页「模板」分组下的「从文件导入模板」
- 走系统文件选择器，选 JSON 文件
- 导入前展示预览（几条模板、分别是什么），确认后才写入

#### 文件格式（我推荐 JSON）

```json
{
  "type": "lifelog-templates",
  "version": 1,
  "templates": [
    { "name": "吃药",       "emoji": "💊", "targetDays": 1,   "tag": "健康" },
    { "name": "中药调理",   "emoji": "🍵", "targetDays": null, "tag": "健康" },
    { "name": "同房",       "emoji": "💗", "targetDays": null, "tag": "夫妻" }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 事件名，与已有事件重名则跳过 |
| `emoji` | 否 | 默认 📌 |
| `targetDays` | 否 | 期望间隔天数，`null` 或不写 = 无固定节奏 |
| `tag` | 否 | 分类标签，用于筛选 |

**为什么选 JSON 而不是 CSV**：

- 与现有导出格式一致，你已经熟悉这套字段
- 能自然表达「可选字段」——CSV 里 `targetDays` 留空和写 0 分不清
- 元宝生成方便，你直接说「给我一份模板 JSON」就行
- 手机上用文本编辑器也能改

**为什么加 `type` 字段**：

导入时要能区分「模板文件」和「数据备份文件」。
两者都是 JSON，没有类型标记就只能靠猜结构——
猜错会把模板当数据导入，或者反过来。

导入时若 `type` 不匹配，明确报错：
「这不是模板文件，请检查后重试」。

## 不做什么

- ❌ 不做模板的编辑与删除（内置模板是静态数据，要改就改代码）
- ❌ 不做模板导出（当前没有强需求，等有人提再说）
- ❌ 不做模板的云端市场/分享（违反离线原则）
- ❌ 不给模板加隐私标记（见下方「待确认」）

## 影响范围

**触及的 spec 模块**：
- `specs/event-management/` —— 新增模板导入相关的两条 Requirement
- `specs/backup-restore/` —— 新增模板文件格式约定

**是否需要重新安装包**：是（新增设置页入口）

**是否会丢数据**：否。模板是新增事件，与已有事件同名则跳过。

## 与项目铁律是否冲突

- [x] 不违反三条铁律
- [x] 不涉及「已确认不做」清单
- [x] 无冲突

模板导入属于一次性批量操作，不影响日常记录路径的摩擦。

## 待确认：一个我需要你决定的问题

**「同房」这类敏感事件，你在意被别人看到吗？**

现在主列表是不设防的——任何人拿起你手机打开 App，
一眼就能看到列表里写着「同房  距今 3 天」。

我不打算自作主张加隐私功能（那是范围蔓延），
但如果这是个真实顾虑，有几个轻量做法：

| 方案 | 成本 | 效果 |
|---|---|---|
| 不加，靠事件名自欺（比如叫「运动」） | 零 | 能糊弄，但你自己也看不直观 |
| 支持归档这类事件，从主列表隐藏 | 低 | 要查看得先进归档，多一步 |
| 加「私密事件」标记，需验证才能显示 | 中 | 最完善，但要引入指纹/密码 |

**我的默认做法：先不加任何隐私机制**（保持简单），
你如果介意，告诉我，我加一条 change 单独做。
