# 技术设计：模板体系增强

## 现状

`从模板导入` 按钮只存在于**空状态页**（`ListScreen.kt:261`）。
一旦有了任何事件，该页面不再显示，入口等于一次性。

根因不是「用户没仔细看」，而是设计缺陷：
首次启动时用户根本不知道自己会用到哪些模板，
让他在那个时刻一次性做完决定，本身就是错的。

## 方案

### 1. 设置页常态入口

新增「模板」分组，与「备份与恢复」并列。
多选列表，已存在的同名事件**置灰并标注「已添加」**。

### 2. 扩充内置模板

现有 24 个基础上补充：

- 健康调理：吃药、中药调理、针灸、贴膏药、量血压、测血糖
- 夫妻日常：同房、约会、结婚纪念日、一起看电影

### 3. 外部 JSON 导入

```json
{
  "type": "lifelog-templates",
  "version": 1,
  "templates": [
    { "name": "吃药", "emoji": "💊", "targetDays": 1, "tag": "健康" }
  ]
}
```

**为什么选 JSON 而非 CSV**：
CSV 里 `targetDays` 留空和写 0 无法区分，
而「有没有固定节奏」恰恰是应用最核心的区分维度。

**为什么加 `type` 字段**：
模板文件与数据备份文件都是 JSON，
没有类型标记就只能靠猜结构，猜错会把模板当数据导入。

导入前展示预览，确认后才写入。

## 取舍

- 不做模板编辑/删除：内置模板是静态数据，要改就改代码
- 不做模板导出：当前无强需求
- 不做云端模板市场：违反离线原则

## 隐私考量

用户已明确「手机不会给别人用」，因此**不加任何隐私机制**。
若将来需要，再单独提 change。
