# 变更提案：疗程模板与子事件场景扩展

change-id：`add-course-templates-and-more-scenarios`

## 背景

疗程（子事件）能力上线后试用，两个使用反馈：

1. **新建疗程太麻烦** —— 要自己填名字、挑图标、挑颜色、选类型、选分类，
   而其中绝大部分在「感冒」这个场景下是完全可预测的
2. **只有吃药能用子事件** —— 其他同样"一段时期 + 多个节奏不同的项"的场景
   （术后恢复、宠物驱虫）目前没法用

## 问题 1：新建疗程要做 5 个决策

当前路径（代码实测）：

```
首页 + → 名称（手输）→ 图标（挑）→ 颜色（挑）→ 类型（选「疗程」）→ 分类（挑）→ 保存
```

5 个决策里，**只有「名称」是真正需要人输入的**，其余 4 项在给定场景后
都能确定。而且名称里真正有信息量的只是「这次和上次的区别」——
通常是日期（感冒 9月11日 vs 上次 8月3日）。

这与产品的第一条铁律冲突：**记录成本必须低到没有借口**。
建个疗程比记一笔还麻烦，用户会干脆不建。

## 问题 2：子事件的适用边界没划清

当前只有「吃药」被设计成子事件（`Templates.CHILD_PRESETS` 全是药），
疗程类型说明写的是「一次看病/一段调理的容器」。

但**数据模型其实已经支持任意类型的子事件**（子事件就是带 `parentId` 的
`Event`，`kind` 可以是频次型、周期型、按需型中的任意一种）。
真正的缺口只是**没有对应场景的模板与预设**。

需要先划清适用边界，避免把疗程变成项目管理工具。

### 判据：三个条件全满足才算疗程场景

1. **有明确终点** —— 结束后整组归档，不再出现在首页
2. **期间有多个「各自节奏不同」的记录项** —— 这也是需要拆分的原因
3. **用户关心的是「这次整体的进度」**，而不是某个单项的长期周期

| 场景 | 终点 | 多项不同节奏 | 判据 | 结论 |
|---|---|---|---|---|
| 看病 / 用药 | ✅ 病好了 | ✅ 退烧药 3/日、消炎药 2/日 | ✅ | **已有** |
| 术后 / 伤后恢复 | ✅ 拆线复查完 | ✅ 换药 2/日、拆线 1 次、复查 7 天 | ✅ | **本次加** |
| 宠物驱虫 / 疫苗 | ✅ 三针打完 | ✅ 疫苗 21 天一针、体内/体外驱虫分开 | ✅ | **本次加** |
| 中医调理 | ✅ 疗程结束 | ✅ 喝药 2/日、针灸每周、忌口 | ✅ | **本次加** |
| 装修 / 搬家 | ⚠️ 跨度数月 | ✅ 几十项 | ❌ 更接近项目管理 | **不做** |
| 备考 / 学习计划 | ❌ | ✅ | ❌ 习惯养成，与铁律 2 冲突 | **不做** |
| 健身计划 | ❌ 循环无终点 | ✅ | ❌ | **不做** |

**不做装修**的理由尤其要说清：它满足条件 2，但疗程页会变成几十项的
长列表，而「结束疗程」遥遥无期——这会把一个「外部记忆」工具拖成
待办清单，正是本产品刻意避开的定位。

## 做什么

### 1. 疗程模板（解决问题 1 的核心）

新增 `CourseTemplate`，一个模板打包好**除名称外的一切**：

| 字段 | 感冒模板的值 |
|---|---|
| 名称前缀 | 感冒 |
| 图标 | 🏥 |
| 颜色 | 健康色 |
| 分类 | 健康 |
| 类型 | COURSE |
| 常用子项建议 | 退烧药 / 止咳糖浆 / 感冒冲剂 |

**创建流程改造**：新建页顶部加「快速开始」chip 行，
点「感冒」→ 图标、颜色、分类、类型**全部自动填好**，
名称预填成「感冒 9月11日」（前缀 + 今天日期，可改），
高级设置（图标/颜色/类型/分类）折叠进「已自动填好，可展开修改」。

用户实际要做的：**点一下模板 → 确认名字 → 保存**，
然后直接进疗程页，常用药以 chip 形式等着被点。

### 2. 「再来一次」—— 从上次复刻（P1，但价值最高）

第二次感冒时，最省事的不是选模板，而是**照抄上次**：

```
新建疗程 → 「再来一次：感冒 8月3日（3 项）」→ 一键生成
          「感冒 9月11日」+ 上次的 3 种药（频次也一起带过来）
```

零输入。这是"只需要手动输入区别部分"的极限形态——
区别部分（日期）系统自己就能生成。

从**最近 3 个疗程**（含已归档）里取，按创建时间倒序。

### 3. 子事件场景扩展（解决问题 2）

按上表新增 3 组疗程模板 + 对应子项预设：

| 疗程模板 | 子项预设 |
|---|---|
| 术后恢复 🩹 | 换药 2/日、拆线（一次性）、复查（周期） |
| 宠物驱虫 🐾 | 体内驱虫、体外驱虫、疫苗（周期） |
| 中医调理 🍵 | 中药 2/日、针灸（周期）、忌口 |

同时补一个已存在的小缺口：**疗程下没有频次型子事件时**，
首页卡片不显示进度（"今日 x/y" 的分母为 0）。
宠物疫苗这种全是周期型子项的疗程会「看起来没状态」。
改为回退显示最紧急子项：「复查 · 该做了」。

## 不做什么

- **不做自定义疗程模板** —— 用户不能自己存模板。
  场景有限（4 个够用），自定义模板要引入模板管理界面，不值
- **不做三层层级**（疗程 → 子疗程 → 子事件）—— 维持两层
- **不做装修/备考/健身类场景** —— 理由见上表
- **不自动创建子事件** —— 模板只给建议 chip，不擅自替用户决定吃哪种药
  （每个人的处方不同，擅自创建比让用户多点一下更糟）
- **不改子事件的数据模型** —— 现有 `parentId` + `kind` 已够用，
  本次只加模板数据

## 待确认

1. **「再来一次」是否本次做** —— 它是 Q1 的最优解，但比模板多一步
   复刻逻辑（要复制子事件及其频次设置）
2. **宠物/中医场景是否现在就要** —— 如果用户实际用不到，
   可以先只做「术后恢复」，模板数据后续再加（成本很低）
