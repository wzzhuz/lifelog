# 拖拽改造：长按选中 → 自由移动 → 松手落位

## 对应反馈

「长按拖拽排序不好用，一次次只能移动一个位置。」

## 核实结论：实现把「连续拖拽」做成了「逐格交换」

当前逻辑：

```kotlin
onDrag = { deltaY ->
    rawOffset += deltaY
    val target = computeTargetIndex(...)   // 只可能返回 current ± 1
    if (target != current) {
        onReorder(current, target)
        draggingIndex = target
        rawOffset = 0f                     // ← 归零，必须再拖半格才能继续
    }
}
```

两个问题叠加：

1. `computeTargetIndex` 最多返回相邻位
2. 每次交换后 **位移归零**，用户必须「再拖半格」才能移动下一格

结果：想从第 10 位移到第 2 位，要**连续拖 8 次**。

## 目标交互

| | 当前 | 目标 |
|---|---|---|
| 选中 | 长按即进入拖拽 | 长按 → 项**高亮**表示已选中 |
| 移动 | 一格一格挪 | **自由移动，可跨多格** |
| 位移 | 每次交换后归零 | **累积总位移**（相对按下点） |
| 落位 | 边拖边落 | **松手才确认** |

## 做什么

### 1. 累积总位移

记录按下时的绝对位置，用「当前位置 − 起点位置」作为总位移，
不做归零。

### 2. 一次移动到目标位

根据总位移**一次性**算出跨过了几项，直接 `move(from, to)`，
而不是反复 ±1。

**难点：项高度不一致。**
分组模式下有分组头（28dp）和卡片（72~112dp），
不能用「位移 ÷ 固定高度」。

必须用 `listState.layoutInfo` 逐项累加**实际尺寸**：

```
从起点开始累加，直到累计尺寸超过总位移 → 即为目标下标
```

### 3. 松手才落位

拖拽期间只更新**视觉位移**（graphicsLayer 的 translationY），
不修改数据列表。松手时才执行一次 `move`。

**好处**：拖拽过程零数据变更、零重组，比边拖边改列表流畅得多。

### 4. 让位动画

上一轮发现 `animateItemPlacement` 已被移除，
替代品是 `animateItem`。本次一并试用；
若 API 仍不可用，则只保留被拖项的动画，并如实说明。

### 5. 视觉反馈

长按选中时：放大 1.04 + 阴影 12dp + 背景色变化，
明确表达「已拿起」。

## 不做什么

- ❌ 不改成右侧固定手柄（实测无误触，长按方案保留）
- ❌ 不做拖拽自动滚屏（事件量通常几十个，够用）

## 影响范围

**触及 spec**：首页交互属视觉细节，不写进 spec；
但拖拽语义变化需同步使用说明页文案。

**是否需要重新安装包**：是
