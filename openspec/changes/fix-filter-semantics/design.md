# 技术设计：筛选器语义

## 根因

两组正交维度被渲染成同一组互斥选项。

数据结构本来就是分开的：

```kotlin
filter: Filter        // 状态，单选
tag: String?          // 分类，单选可空
```

但 UI 把它们平铺进同一个 `LazyRow`，样式完全一致，
用户只能从视觉推断关系——自然会推断成互斥。

**修的是呈现，不是逻辑。**

## 方案

### 1. 两行分组

`FilterRow` 组件：左侧 34dp 的维度标签，右侧横向滚动的 chip 组。

```
状态   [不限] [该做了] [待记录] [已钉选]
分类   [不限] [个人] [家务] [健康] [汽车]
```

维度标签是关键的视觉锚点——没有它，两行仍然像一组。

### 2. 改名

「全部」→「不限」。

「全部」语义是「包含一切」，选中它却还能被分类过滤，自相矛盾。
「不限」准确表达「本维度不做限制」。

### 3. 分类行从全部事件推导

```kotlin
// 修前：从可见事件推导，选中后会把自己筛没了
val allTags get() = all.mapNotNull { it.event.tag }...

// 修后：allTags 是独立字段，由 ViewModel 从完整列表计算
allTags = statuses.mapNotNull { it.event.tag }.distinct().sorted()
```

## 不做的事

- 不改成多选标签：会让「与/或」语义再次变模糊
- 不合并维度：它们本来就该分开

## 验证

- [x] 选「不限」+「汽车」→ 显示汽车分类下所有状态
- [x] 选中某分类后，分类行仍显示全部可选项
