# 增量：新建入口按路径分流

## ADDED Requirements

### Requirement: 新建入口按路径分流

点击新建时，系统 SHALL 先让用户选择路径：
「记一件事」或「开一个疗程」，两者**各自成页**，不再共用一张表单。

理由：单一表单同时承担三条路径（记件事 / 开疗程 / 建子事件），
每加一个能力就往里塞字段和条件分支，复杂度累加。

#### Scenario: 记一件事只需要填名字

- **GIVEN** 用户点击新建并选择「记一件事」
- **WHEN** 进入创建页
- **THEN** 首屏只呈现名称输入
- **AND** 图标、颜色、类型、分类、备注收进「更多设置」且默认收起
- **AND** 这些字段均有默认值，**不展开也能保存**

#### Scenario: 开疗程走独立页面

- **GIVEN** 用户点击新建并选择「开一个疗程」
- **WHEN** 进入疗程创建页
- **THEN** 看到疗程模板以卡片形式呈现（含每个模板的子项清单）
- **WHEN** 用户选择某个模板
- **THEN** 名称被预填为「模板前缀 + 当天日期」
- **AND** 用户确认后直接创建并进入该疗程详情页

### Requirement: 子项预设按疗程场景收敛

从模板创建疗程后添加子事件时，系统 SHALL 只呈现该疗程场景
对应的常用项预设，而不是全部预设。

疗程场景 SHOULD 由疗程名反查模板得出；匹配不到时
（手动创建的疗程、用户改过名字）系统 SHALL 回退为
按场景分组展示全部预设，不得因此无法添加。

#### Scenario: 感冒疗程只给感冒相关的项

- **GIVEN** 疗程「感冒 9月11日」由感冒模板创建
- **WHEN** 用户在该疗程下添加子事件
- **THEN** 常用项只显示退烧药、止咳糖浆、感冒冲剂、消炎药

#### Scenario: 改过名字的疗程仍可添加

- **GIVEN** 疗程名已被用户改为不匹配任何模板的名字
- **WHEN** 用户添加子事件
- **THEN** 常用项按场景分组展示全部预设

## REMOVED Requirements

### Requirement: 新建事件页内嵌疗程模板选择

已移除：疗程模板选择从新建事件页迁到独立的「开一个疗程」页面。

移除原因：模板 chip 挤在新建页顶部，让「记一件普通事」这条
本该最简单的路径也变得复杂——加疗程功能反而拖累了普通事件创建。
