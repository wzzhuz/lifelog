# 变更提案：新建入口按路径分流

change-id：`split-create-entry-by-path`

## 背景

疗程模板上线后实际试用，反馈是「新建事件页越来越杂」。

## 根因：新建页被当成了万能表单

当前 `EditEventScreen` 一屏同时承担三条完全不同的路径：

| 路径 | 需要填的 | 决策数 |
|---|---|---|
| 记一件普通的事 | 名称（+可选间隔） | 1 |
| 开一个疗程 | 名称、图标、颜色、类型、分类、子项预设 | 5 |
| 建一个子事件 | 名称、频次、归属 | 2 |

三者靠 `if (draft.parentId != null)` / `if (draft.kind != COURSE)`
这类分支控制显示什么。每加一个新能力就往里塞字段和分支，
**复杂度是累加的**——界面变杂不是疗程模板的错，是入口没分流。

顺带一个反直觉的后果：记一件普通事件本来只要 1 个决策，
现在被疗程路径拖着，第一屏就摆着「快速开始」四个模板，
反而比加疗程功能**之前**更麻烦。

## 方案：点「+」先选路径

```
点 +
├─ 记件事（默认，主按钮） → 名称为主，其余全部收起且有默认值
└─ 开疗程                → 选模板 → 确认名字 → 直接进疗程页加药
```

两条路径各自成页，不再互相挤占。

### 「记件事」路径反而变简单

- 第一屏只有名称
- 图标 / 颜色 / 间隔 / 分类 / 备注收进「更多设置」，**默认收起**
- 且全部有默认值：**不展开也能直接保存**

这是本次最重要的收益：加疗程功能时把普通事件的创建路径也拖累了，
现在把它还回去。

### 「开疗程」路径独占一屏

模板选择有整屏空间，每个模板是一张卡片（图标 + 名称 + 一句话说明 +
会包含哪些子项），不再是挤在表单顶部的一排 chip。

选完模板 → 确认名字（预填「感冒 9月11日」）→ 创建 → 直接进疗程详情页。

## 做什么

1. 点「+」弹出二选一（记件事 / 开疗程）
2. 「记件事」走精简后的编辑页：更多设置默认收起，不展开也能存
3. 「开疗程」走独立的模板选择页
4. 子项预设按疗程场景收敛：从模板创建的疗程只显示该场景的 3~4 个预设
5. 移除编辑页里的「快速开始」模板 chip 行（已迁到独立页面）

## 不做什么

- **不改数据模型** —— 疗程模板、子项建议的结构保持原样
- **不删子事件的独立创建入口** —— 疗程详情页「添加子事件」照旧
- **不做三选一** —— 子事件不占顶层入口，它天然属于疗程内
- **不合并两条路径** —— 分流的意义就是让它们各自简单

## 验收

对比两个包：

| | 旧（模板挤在新建页） | 新（分流） |
|---|---|---|
| 记件普通事 | 首屏见 4 个模板 chip | 首屏只有名称 |
| 开疗程 | 找模板 → 再核对 4 项 | 选模板 → 确认名字 |
| 新建页字段数 | 名称+快速开始+图标+颜色+类型+分类 | 名称（其余折叠） |
