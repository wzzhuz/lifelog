## 一、定位

**不是待办清单，不是习惯打卡，是「上次什么时候做」的外部记忆。**

三条贯穿全部设计的铁律：

1. **记录成本必须低到没有借口** —— 最快路径是「一次点击」，而不是「打开 App → 找到事件 → 记一笔」
2. **不打卡、不算连续天数、不制造焦虑** —— 晚两天换床单不是失败
3. **数据是你的** —— 不申请任何网络权限，代码里连 `INTERNET` 都不声明

### 与同类应用的差异

| 应用 | 能做什么 | 缺什么 |
|---|---|---|
| TimeJot | 记录事件 + 距今天数 + 备注 + 照片 | 只显示天数，不判断「该不该做」；记录多了列表卡顿、图片偶有问题 |
| Tasks.org | 重复任务「从完成日期起算」 | 是任务管理器逻辑，杂事记录太重 |
| Loop Habit Tracker | 习惯打卡 + 统计 | 打卡制，没有单条备注和照片 |
| **生活手记** | 一键记录 + 自动判断状态 + 备注照片 + 时间线回顾 | — |

核心增强：**没有固定周期的事件（比如看病）会自动学习你的节奏**。
记满两次后按历史平均间隔判断状态，而不是只显示一个冰冷的天数。

## 二、核心设计：把「记录」拆成四个摩擦层级

| 层级 | 入口 | 步数 | 适用场景 |
|---|---|---|---|
| L0 | 桌面小组件（单事件型） | 1 步 | 理发、换床单这类高频项 |
| L1 | 首页「随手一点」横向栏 | 1 步 | 钉选的常用事件 |
| L2 | 应用内卡片 ✓ 按钮 | 2 步 | 通用兜底 |
| L3 | 详情页「带备注记」 | 3 步 | 需要写备注、拍照、倒填日期 |

**关键取舍**：L0–L2 只记「当前时间 + 无备注」，快到极致；
需要写东西时才进 L3。两类场景分开优化，不混在一起。

## 三、功能清单

### P0 核心

**事件管理**
- 新建 / 编辑 / 删除 / 归档
- 属性：名称、emoji 图标、颜色、期望间隔天数、分类标签、备注
- 预置模板库 34 个，覆盖个人、家务、健康、汽车、宠物、数码、财务、人际、夫妻等分类，设置页常驻入口可反复导入

**记录**
- 一键记录当前时间（L0–L2 共用）
- 带备注记录：文字 + **倒填日期时间**（昨天理的发，今天补记）
- 照片附件（看病拍化验单、理发拍发型），压缩到长边 1600px
- 记录可编辑、可删除

**查看与决策**
- 列表卡片：距今天数大字 + 状态色条
- 详情页：统计块（累计次数 / 平均间隔 / 判断基准，均基于全量记录）
  + 时间线（分页加载，首屏 20 条，可加载更早）
- 预测下次日期
- 全局搜索（事件名 + 备注全文 + 标签）

**数据安全**
- 导出 JSON / ZIP（含照片）/ CSV
- 导入（自动合并，不覆盖）
- 每次修改后自动保留最近 4 份本地备份

### P1 决策增强

- 钉选置顶（同步到首页「随手一点」栏）
- 标签分组筛选
- 归档（不常用但不舍得删的事件）

### P2 主动增加的

1. **全局时间线** —— 所有事件混排按时间倒序，回答「上个月我都干了些啥」
2. **年度回顾** —— 一年理发 8 次、看病 3 次、换床单 24 次
3. **CSV 导出** —— 用 Excel 打开做透视分析
4. **Material You 动态配色** —— Android 12+ 取壁纸色，视觉上像系统自带应用

### 已确认不做

按用户要求，以下功能**明确砍掉**：

- ❌ **Quick Settings 磁贴**（不需要锁屏记录）
- ❌ **到期提醒通知**（用户习惯是「需要确认时主动打开查看」，提醒反而变成打扰）

其余同样不做：云同步、账号体系、连续打卡、成就徽章、排行榜、统计埋点、广告 SDK。

## 四、状态计算逻辑

这是整个应用的核心，也是「做出决策」的落点：

```
若无记录
  → 待记录（灰）
否则
  实际天数 d = now - lastTimestamp
  基准 t = 期望间隔 ?: 历史平均间隔(记录数>=2) ?: 30天兜底
  ratio = d / t
  ratio >= 1      → 该做了（红）
  ratio >= 0.75   → 快到了（黄）
  否则            → 新鲜（绿）
```

**为什么用历史均值兜底**

看病这类事没有规律，不可能提前设间隔。记满两次后系统自动学会你的节奏
（比如「平均 3 个月」），之后就按这个判断。

**为什么不要求必须设间隔**

设间隔这件事本身就是摩擦。用户可能刚装 App 时根本不知道自己多久理一次发。
允许「先记着，之后系统自己算」能大幅降低起步门槛。

## 五、界面结构

```
主界面（事件列表）⭐ 默认页
├─ 顶栏：搜索入口、时间线、设置
├─ 搜索框
├─ 「随手一点」横向快捷栏（钉选项，点即记）
├─ 筛选 chips：全部 / 该做了 / 待记录 / 已钉选 / 分类标签
└─ 卡片列表（状态色条 + 距今天数 + ✓ 按钮）

时间线
└─ 所有事件混合，按时间倒序，按月分组

设置
├─ 备份与恢复（JSON / ZIP / CSV 导出，导入）
├─ 外观（跟随系统 / 浅色 / 深色）
├─ 年度回顾
└─ 关于

二级页
├─ 事件详情（统计块 + 时间线 + 记现在 / 带备注记 / 钉选 / 归档 / 删除）
├─ 带备注记录（日期时间 + 文字 + 照片）
├─ 新建 / 编辑事件
└─ 年度回顾（可切换年份）
```

## 六、桌面小组件

两种形态都提供，用户自己往桌面放：

| 形态 | 尺寸 | 行为 |
|---|---|---|
| 列表型 | 4×2 | 显示最多 5 个事件（钉选优先 + 最久没做的优先），点击打开应用 |
| 单事件型 | 2×2 | 大字显示距今天数，**点击直接记一笔**（静默记录，不闪界面） |

单事件型添加时会弹出配置页让用户选择具体事件。

| 权限 | 用途 | 必需 |

| `CAMERA` | 给记录拍照 | 否（无相机设备自动降级） |

## 八、与网页版的关系

开发过程中先产出了一个单文件网页版（`生活手记.html`）用于快速验证需求。

两版数据格式**兼容**：网页版导出的 JSON 可以直接导入原生版，
早期在网页版记的数据不会浪费。

两版定位不同：

- 网页版：零安装门槛，适合先验证「记录这件事本身能否坚持」
- 原生版：有桌面小组件、真实本地数据库、更好的性能，摩擦更低
